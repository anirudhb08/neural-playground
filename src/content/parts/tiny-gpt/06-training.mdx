Everything so far can *measure* how wrong the model is. Nothing reduces it.

There is a table of numbers, and a single figure saying how badly they are
doing. What is missing is the part that changes one because of the other — and
it is smaller than you would expect.

## Which way is downhill?

Imagine looking for the lowest point of a valley in thick fog. You cannot see
where the bottom is. But you can feel the ground under your feet, and that tells
you which way is down and how steep it is.

Take a small step that way. Feel again. Repeat.

That is the whole method, and the slope under your feet has a name: the
**gradient**. It answers one question, asked of every number in the model at
once — *if I nudge you up slightly, does the score get better or worse, and by
how much?* The step is then always the same rule:

```
new value = old value − learning rate × slope
```

Minus, because the slope points uphill and uphill is where the model is worse.
The **learning rate** is how big a step to take: too small and you are there all
day, too large and you stride straight past the bottom.

<aside class="aside measure mt-5">
The [other tutorial](/neural-networks/06-learning/) works through why that rule
finds a minimum, with a network you can push around by hand. This part takes the
rule as given and does something the other one could not: for a model this
small, the gradient is short enough to write out and check.
</aside>

## The gradient, in one line

For this model it really is one line, and it is worth seeing because it kills
the idea that gradients are produced by magic.

Each prediction hands out blame. Every character's score gets blamed by exactly
the probability the model gave it — **except the right answer, which gets one
subtracted**. So a character the model was confident about and wrong collects a
lot of blame; one it was confident about and right collects almost none.

```python
d = probs.copy()
d[range(N), answers] -= 1
```

That is the derivative of the loss with respect to the scores. Everything after
it is bookkeeping: send each prediction's blame back to the table row it was
read from, and add up where a row was used more than once.

<aside class="aside measure mt-5">
This is not a simplified stand-in for the real thing. Run the same batch through
PyTorch's `loss.backward()` and the two gradients differ by 1.4 × 10⁻¹⁷ — the
smallest gap two 64-bit numbers can have. The library computes exactly this,
faster and for models where writing it out by hand would be unreasonable.
</aside>

## Four lines, and it learns

```python
for step in range(600):
    xb, yb = get_batch()
    table -= learning_rate * gradient(table, xb, yb)
```

Take a batch. Work out which way is downhill. Step. Repeat. Every model in this
tutorial and every model anywhere is this loop with something more elaborate in
the middle.

## Is that good?

A number going down is not the same as a number being good, so it is worth
having something to measure against. There are two marks, and both come out of
the text rather than out of the air.

The upper line is what a model that knows nothing scores: every character
equally likely, which for a thirteen-character vocabulary is `ln(13)` —
**2.5649**. The table starts as zeros, so training opens exactly there.

The lower line is the best that *anything* seeing one character can possibly do.
It is a property of the text, not of any model — how unpredictable this sentence
actually is, given one character of context. That figure is **0.7889**, and no
amount of training gets underneath it.

<div class="claim mt-7">
Six hundred steps take it from 2.5649 to about 0.86. The floor is 0.7889.
</div>

The figure above and the notebook below will not agree to the last digit, and
neither is wrong: each draws its own random batches, so each takes a slightly
different path down. They finish in the same place.

## What it actually learned

Here is the part worth stopping on. Ask the trained table what follows `t`, and
ask [the table built by counting](/tiny-gpt/02-counting-pairs/#what-does-count-the-pairs-mean) the same thing:

| after `t` | learned by training | counted directly |
|---|---|---|
| space | 55.4% | 50.0% |
| `h` | 42.7% | 50.0% |

Nobody told the loop to count anything. It never saw a tally. It was shown a
wrongness score and which way to move, six hundred times, and it arrived at
approximately the table that counting produces in one pass.

<div class="claim mt-8">
Gradient descent rediscovered counting, without being told that counting was
the answer.
</div>

That is the reason this is worth doing for a model where counting was already
possible. Counting stops working the moment the model needs to weigh several
characters against each other, which is the next thing that happens. Nudging
does not.

## Why the line wobbles

The curve does not fall smoothly — it drops, jitters, sometimes climbs for a
stretch. That is not a bug and it is not a failed run.

Each step judges the table on four short chunks picked at random, not on the
whole text. Four chunks are not a fair sample of anything, so the direction they
suggest is roughly downhill rather than exactly. Individual steps go the wrong
way; the trend does not.

Using the whole text every step would give a smooth curve and be far slower, and
at real scale it is not an option at all. The noise is the price of not looking
at everything, and it is a price worth paying.

## It still sees one character

Same wall as ever. The model is a bigram — a good one now, near the best a
bigram can be, and still incapable of remembering that it wrote `sat`.

The difference is that it got there by being corrected. That mechanism does not
care how complicated the thing in the middle is, which is why the next part can
make it much more complicated.
